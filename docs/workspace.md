# 桌面工作区设计（首版）

## 页面结构

- 顶部主导航包含工作区、模型、技能、OpenCode 终端、轨迹、调用列表、仪表盘和设置。「模型」管理全局提供商及模型，「技能」管理应用技能副本。
- 工作区左侧按项目显示 OpenCode 对话，项目列表默认折叠，点击项目标题展开；右侧显示对话、文件改动和活动。这里的“活动”汇总当前 OpenCode 对话的模型请求和工具步骤，顶部“轨迹”是代理录制的模型调用轨迹。
- 项目目录继续保存在现有的 `terminal-projects.json`，这样旧版保存的项目会直接出现在新工作区。对话及消息由 OpenCode 自己持久化，本应用只记住本次页面访问选中的项目和对话。

## 进程与数据流

```text
Tauri 窗口 / Web 页面
        │
        ▼
FastAPI 工作区 API ──► WorkspaceManager ──► opencode serve（每个项目一个本地进程）
        │                                           │
        │                                           └─► 现有 LLM 代理 ──► 调用记录 / 轨迹
        └─► 原有仪表盘、调用列表、轨迹、设置 API
```

OpenCode 服务只监听 `127.0.0.1`，使用每次启动随机生成的 HTTP Basic 密码。页面通过同源的 FastAPI API 获取会话、消息、文件差异和权限请求；SSE 与定时刷新用于更新进行中的对话。应用关闭或影响 OpenCode 的设置变化时，关闭由工作区启动的服务进程。

未启动项目服务时，可通过只读 SQLite 快照浏览历史；快照中缺少会话时必须交给原生 HTTP API 确认，不能直接认定会话不存在。项目服务已运行后，会话及消息读取以该服务为准。发送队列的会话校验、运行状态和回复完成检查始终读取实际接收任务的服务，避免历史快照与原生数据库不一致时阻塞新会话、旧会话或 fork 会话。

## OpenCode 功能入口

工作区对接的是 OpenCode 官方 `opencode serve` HTTP API。顶部的 **OpenCode 终端** 入口启动原生 TUI；需要尚未移植到工作区的命令、快捷键、插件交互或完整终端体验时，可从那里使用。如果 `opencode` 位于 PATH，通用 shell 会话也可执行 OpenCode CLI。接口以安装包锁定的 OpenCode 版本为准，发布前应核对该版本的 `/doc` OpenAPI 描述。

| 能力 | 工作区 | 原生终端 |
|---|---|---|
| 项目、会话历史、新建/重命名/删除/分支 | 已支持 | 已支持 |
| 文字、模型/推理强度和 Agent、斜杠命令与 shell 命令 | 已支持 | 已支持 |
| 发送图片/PDF/文本附件 | 工作区不提供入口 | 已支持 |
| 消息、Markdown、思考过程、工具活动、文件差异 | 已支持 | 已支持 |
| 待办、子对话、权限和交互式提问 | 已支持 | 已支持 |
| 停止、上下文压缩 | 已支持 | 已支持 |
| 输出期间排队发送、编辑和移除待发消息 | 已支持（V1 兼容队列） | 依原生版本行为 |
| 回退/恢复、会话共享 | 工作区不提供入口 | 已支持 |
| Provider API Key | 已支持 | 已支持 |
| 本地技能导入、删除、启停、`/skills` 选择和 AI 自动加载 | 已支持 | 使用原生技能发现与命令；管理后需重启已有终端 |
| OAuth 登录、MCP/插件管理、主题与快捷键、文件符号搜索等进阶交互 | 使用原生终端或 OpenCode 配置 | 已支持 |

桌面侧栏可整体收起，移动端可关闭遮罩；单个项目的对话列表默认折叠。对话视图按日期分隔消息并汇总同一轮回复的工具步骤；文件改动页显示统计和逐行差异，OpenCode 未返回差异时仍列出已写入的文件；活动页显示模型请求和工具事件的时间线。历史消息中的附件仍可查看。

对话顶部状态图标右侧提供当前项目的目录树入口。目录树可以放在对话左侧或右侧，浏览器记住最后选择的位置；顶部支持文件名和路径的模糊搜索，深层目录保留完整文件名并支持横向滚动。搜索和回复中的文件识别使用本地只读文件索引，不启动原生服务，不跟随符号链接，也不扫描隐藏目录或依赖、构建输出。索引最多包含 20,000 个文件，扫描最多 50,000 个条目或 3 秒，达到限制时搜索区会提示；其余目录仍可逐层展开。

用户消息中的文件引用和 AI 回复中可唯一识别的项目文件显示为蓝色，点击后打开目录树、展开父目录并定位文件。只有 basename 且存在重名的文件不会自动链接；完整相对路径可准确定位。`@` 文件选择器优先保留完整文件名，较长的父路径从前端省略，引用序列化及提示仍保留原始路径。有效斜杠命令和技能在输入框内使用相同的蓝色高亮。

思考过程在生成期间默认展开，直接应用 V1 `message.part.updated` 和 `message.part.delta` 事件，以逐帧批量追加文字的方式快速展示。思考区域按内容自适应高度，最长 280px，超出后独立滚动；忽略末尾空白，避免短思考占据大块空白。连续增量复用消息、展开区域和文本节点，保留用户手动折叠状态与滚动位置；停留在底部时跟随新增内容，向上查看时不强制滚回底部。技能正文按容器宽度换行。回复支持 Markdown 表格、列对齐、单元格内格式和横向滚动，代码块中的表格示例保留代码展示。点击项目加号会立即显示新的空白对话并允许输入草稿，原生会话在后台创建；完成后迁移草稿，切换到其他对话不会被延迟返回的创建结果打断。

技能管理页就地读取原 OpenCode 配置目录，以及原生支持的 `~/.claude/skills`、`~/.agents/skills`，标注来源，不复制外部文件。原生自动发现的目录不重复注入 `skills.paths`；遵守 `OPENCODE_DISABLE_EXTERNAL_SKILLS` 和 Claude 兼容禁用开关。项目 `/skills` 选择器继续以原生实际加载的目录和 Agent 权限为准，包含项目及祖先目录中的技能。外部同名技能以原生实际位置为准；应用副本优先且冲突会提示。启停仅写入应用隔离配置的技能权限，删除仅作用于应用副本。

## 输出期间排队发送

模型执行中继续输入，按 Enter 或点击「加入队列」，本轮结束后依次处理。输入框上方的紧凑列表显示待发顺序、内容摘要、模型和 Agent；可以编辑任务内容、移除消息，或者暂停整个队列。普通消息、图片附件、项目文件引用和原生技能/斜杠命令保留加入队列时的选择；终端 `!` 命令需要等任务和队列结束再运行。

空闲会话的新消息在后端核对原生状态后立即开始派发，响应返回时已标记为发送中，不短暂展示为待发送。刚完成的已跟踪回复会先清理再派发下一条；忙碌或暂停的队列仍按顺序等待。原生命令派发在后台执行，不等待整段 AI 回复才释放输入框；派发和队列轮询按会话互斥，防止重复提交。

队列由应用后端处理，不依赖当前浏览器页面，切换对话和刷新不影响执行。停止任务会先暂停该会话队列；请求/模型失败也暂停后续消息。待发内容保存在应用配置旁的 `workspace-queue.json`，应用重启或需要重启工作区的配置更新后需点击「继续发送」。发送状态未确认时不会自动重发；已提交项可移出队列，但这不会撤回 OpenCode 中已发送的消息。每个会话最多保留 20 条队列项。

当前使用 V1 `/session/{id}/prompt_async` 和 `/session/{id}/command`，通过 `/session/status` 和原生消息 ID 确认前一条回复完成后再发送下一条，原生会话仍由 OpenCode 保存。V2 官方 API 的 `delivery: "queue"` 不适用于本项目的 V1 服务；此实现不升级 OpenCode 或混用 V2 接口。队列内容只在实际调用原生命令时记录技能使用元数据，并在发送前重新校验模型、技能权限及项目文件边界。

## 模型管理与两种 OpenAI 接口

顶部「模型」页面独立管理应用提供商和手动模型，不依赖工作区项目或 OpenCode 服务启动。模型定义、真实密钥、应用默认模型和原生目录显示开关保存在应用配置；`GET /models/config` 仅返回密钥状态和 revision，`PUT /models/config` 使用 revision 防止覆盖其他页面的修改。省略 `api_key` 表示保留，空字符串表示清除。旧模型可保持未填写的限制；新增或修改模型必须填写正整数的 `context_length`、`output_length`。

Sona 网站模型默认上下文为 256K（262144 tokens），输出为 32K（32768 tokens），同时用于原生模型配置与会话上下文用量显示。网站登录 token、场景密钥和订阅模型保存在配置文件旁的 `*.sona-sessions` 私有文件中，按环境和网站地址隔离；Windows 使用当前用户 DPAPI 加密，其他系统文件权限为 0600。普通配置、管理接口和浏览器缓存不包含网站凭据。退出登录或确认 token 失效时同步清除保存的登录。

Sona 订阅模型没有缓存过期时间：打开模型弹窗直接使用已获取的模型；手动刷新或每次 App 启动时的后台刷新更新目录。启动刷新失败时保留已有目录，认证失效则显示登录按钮。工作区模型弹窗可以直接完成浏览器登录，无需跳到设置。成功回调立即尝试关闭浏览器页；浏览器不允许关闭时回到 Sona 网站首页，避免停留在本地回调地址。

共享环境构造器把提供商编译成 `sonacode-<base64url-name>`，通过 `OPENCODE_CONFIG_CONTENT` 注入两个 V1 原生适配器、模型限制、modalities 与明确配置的 variants。模型 `provider.api` 决定实际 API 根地址，`provider.npm` 决定 Chat Completions 或 Responses；不能用模型 `options.apiKey` 覆盖 SDK 密钥。直连通过模型 headers 使用有效密钥，空凭据显式覆盖环境/认证回退；代理模式不把真实 Key 放进 OpenCode，而使用 `/managed/<provider-token>/<model-token>/…` 路由由应用注入有效 Key。路径令牌不含密钥，未知标识返回 404；原 `/up/{name}/…` 路由和默认上游保留。

原生模型默认不显示；打开后按当前项目合并显示，其接口及路由保持原生行为。应用模型不可通过旧 OpenCode `/auth` 写入端点修改密钥。后台发送也校验模型是否仍存在、思考强度和附件是否支持，防止陈旧选择继续发送。

未配置默认强度时注入 `reasoningEffort: null` 覆盖 OpenCode 根据模型名称推断的默认值，避免 GPT-5 等名称自动发送未配置的 `medium`；用户选择的 variant 或配置的默认档位再显式覆盖。

Responses 解析在后台处理 `input`、`instructions`、function call/output、非流式 output 和 SSE 的文本/思考摘要/工具参数事件。两种接口统一记录输入/输出/缓存/思考 Token、TTFT、工具调用与完成/错误状态；未知 Responses 事件保存在 parsed metadata。`response_id` 与 `previous_response_id` 按提供商关联已有记录，会话头仍优先；父记录未捕获时展示历史不完整提示。原始请求/响应字节不做协议转换。

原生兼容测试使用临时 XDG 目录及本地 mock 服务，不访问真实模型、不使用用户凭据：

```bash
OPENCODE_TEST_BINARIES=/path/to/opencode-1.18.18:/path/to/opencode-1.18.32 .venv/bin/python -m pytest tests/test_models_native.py -q
```

该测试读取每个运行版本的 `/doc`，验证 V1 路径，并实际执行直连和代理模式下的 Chat Completions、Responses、独立 Key、无 Key 和 reasoning effort 请求。界面检查截图属于 `.runtime/model-ui-check/`，不提交运行数据。

## 多会话并发与输入草稿

当前 V1 接入支持同一项目的多个会话同时执行，也支持多个项目同时执行。每个项目使用独立 `opencode serve`，每个会话使用自己的原生 session ID、消息历史、状态和 FIFO 队列。任务派发仅在短暂登记期间保护技能配置，不会把不同会话的模型执行串行化；切换界面不会停止后台会话。停止按钮只作用于当前会话。并发会话仍共享同一个项目目录，修改相同文件需要自行协调。

侧栏每个会话右侧、整行垂直居中的蓝色小旋转图标表示正在运行或重试。当前项目通过原生事件更新，其余已经启动的项目通过聚合状态接口持续刷新；该接口不会为状态查询额外启动未打开的项目。状态暂时读取失败时保留最近已知状态，等待下一次刷新。列表只保留第二行更新时间，刷新复用会话和动画节点，避免旋转重新开始。

未发送草稿按“项目 ID + 会话 ID”独立保存，切换会话/项目后恢复文字、技能命令、文件引用和已读取的图片。发送成功只清除对应草稿；发送失败或发送期间修改的文字会保留。文字和附件尝试保存在当前浏览器标签页的 sessionStorage，刷新可恢复；关闭标签页后不保证保留。图片超过浏览器存储配额时仍在内存中保留，支持当前页面内切换。草稿不会提交给 OpenCode，也不会写入项目文件。

兼容验证使用 OpenCode 1.18.18 与安装包锁定的 1.18.32，检查运行中第二个会话能够完成回复、各原生消息携带正确 session ID，以及停止第二个会话不会中断第一个。接口依据 [官方 V1 Server 文档](https://dev.opencode.ai/docs/server/) 的 `/session/{id}/prompt_async`、`/session/status` 和 `/event`。

右下角上下文用量使用原生 V1 消息的 `info.tokens`（输入、输出、推理、缓存读写之和）和 `/config/providers` 返回的模型 `limit.context`，与 OpenCode 官方上下文组件采用相同统计口径。当前会话的 `message.updated` SSE 事件直接更新统计，不等待其他接口；新助手消息的初始零用量不会覆盖最近有效样本，旧的在途历史响应也不会覆盖较新的事件。准确用量通常在每次模型调用结束时上报，生成中保持最近有效值，并非逐 Token 的实时计数。

输入框底部的「本轮耗时」按 `小时:分钟:秒` 显示，例如 `1:5:35`。每次用户发送消息立即归零，每秒更新，包含排队等待、思考和工具执行，回复完成或停止后保留最终耗时。切换会话时显示对应会话的计时；重新打开历史会话时根据最后一轮原生消息的时间恢复处理耗时。旁边的「模型」「工具」仍显示整个会话的累计用时。
